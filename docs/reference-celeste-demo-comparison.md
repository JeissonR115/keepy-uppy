## Reference project structure and behavior

The character implementation is a two-layer controller: `CelesteExample/Scripts/Player.gd` extends `addons/PixelPerfect2D/Platformer/CharacterControllerPlatformer.gd`, which itself extends `CharacterController.gd` and reads a `PlatformerResource`. `Celeste.tres` supplies the demo tuning. The base handles horizontal acceleration/friction, cooldowns, and one dash charge that refills on floor contact. The platformer controller adds gravity, variable jump cutting, coyote time, jump buffering, wall checks/sliding, wall jumps, and corner correction. Its tuning resource includes a 0.1 s coyote interval, 0.1 s jump buffer, 0.1 s wall-jump input cooldown, 0.05 s wall-jump buffer, 3 px wall safe margin, and 4 px corner correction. Dash direction and tuning are implemented in the shared controller/resource; the demo player script chooses movement direction or facing direction and triggers presentation effects.

`CelesteExample/States/` contains `idle`, `run`, `jump`, `fall`, `climb`, and `flip` state scripts driven by `Utils/StateSystem/Scripts/StateMachine.gd` and `State.gd`. `Player.tscn` combines an `AnimatedSprite2D`, `AnimationPlayer`, collision shape, that state machine, a `Hair` subscene, dash particles, and a viewport-based dash afterimage layer. `Hair.gd` tracks recent player positions in a `Line2D`, clamps point spacing, and mirrors animation hair anchors on turns. `Player.gd` uses jump/land/dash signals for squash, hair color, particles, screen shake, shockwave, and afterimages. Its dash path includes `OS.delay_msec(30)`, which must not be copied into a shared two-player simulation because it blocks the process.

The sample game is not built from a TileSet or TileMap. `CelesteExample/Scenes/game.tscn` draws `celestetiles.png` and `celestebg.png` as `Sprite2D` nodes and defines one hand-authored compound `CollisionPolygon2D` under `TileStaticCollision`. No terrain sets, per-tile metadata, tile collision polygons, or map layers exist to migrate. `game_view.tscn` provides a 320×180 pixel viewport, camera/shake, scene manager, debug menu, and overlays.

Runtime/editor dependencies visible in `project.godot` include the PixelPerfect2D singleton/plugin and debug menu plugin. Movement also depends on the PixelPerfect2D platformer classes/resource, the local state system, `Utils/Collision`, the particle system, shockwave scenes/scripts, camera scripts, and the scenes/assets they reference. `PixelPerfect2D/plugin.cfg` attributes that plugin to Eneskp but provides no license. The repository has no root `LICENSE`, `COPYING`, or `NOTICE`; the bundled debug menu has an MIT license, which applies to that component only.

## Rights and import decision

The README states that Celeste asset rights belong to EXOK and that the demo uses the assets with permission. The inspected repository does not include the permission terms or a project-level code license that establishes rights to redistribute its Celeste graphics, PixelPerfect2D source, or all other resources in Keepy Uppy. Therefore no reference code, graphics, tile data, or scenes are copied by this change unless separate applicable terms are established. The demo itself contains no reference TileSet to copy. Keepy Uppy retains its pre-existing local player graphics, cape, arena TileSet, and role-based arenas; the graphics' creator and redistribution terms are not established by this audit.

## Primary reference — `lvlzyro/Celeste-Movement` (redirects to `yusufkaanocak/Celeste-Movement`)

- Repository: [source repository](https://github.com/yusufkaanocak/Celeste-Movement), branch `master`, inspected at commit `1322a72d358296593a4c4272e515d968bae852e2` (2020-02-22). `project.godot` declares `config_version=4` and `player/player.gd` extends `KinematicBody2D`, confirming Godot 3-era project/API. Its exact minor version is not declared.
- Main implementation reviewed: [`player/player.gd`](https://github.com/yusufkaanocak/Celeste-Movement/blob/1322a72d358296593a4c4272e515d968bae852e2/player/player.gd), [`project.godot`](https://github.com/yusufkaanocak/Celeste-Movement/blob/1322a72d358296593a4c4272e515d968bae852e2/project.godot), [`player/player.tscn`](https://github.com/yusufkaanocak/Celeste-Movement/blob/1322a72d358296593a4c4272e515d968bae852e2/player/player.tscn), [`scenes/Demo.tscn`](https://github.com/yusufkaanocak/Celeste-Movement/blob/1322a72d358296593a4c4272e515d968bae852e2/scenes/Demo.tscn), root README and [`LICENSE.md`](https://github.com/yusufkaanocak/Celeste-Movement/blob/1322a72d358296593a4c4272e515d968bae852e2/LICENSE.md). The project uses one `KinematicBody2D`, raw shared Input Map actions and `move_and_slide(velocity, Vector2.UP)`. Its frame-based `MAX_COYOTE_TIME=6`, `JUMP_BUFFER_TIME=10`, and wall-jump timing must be translated to seconds at the project's 60 Hz physics rate rather than copied as frame counters.
- The script declares `ACCELERATION=3000`, `MAX_SPEED=18000`, `LIMIT_SPEED_Y=1200`, `GRAVITY=2100`, `JUMP_HEIGHT=36000`, `MIN_JUMP_HEIGHT=12000`, `WALL_JUMP_AMOUNT=18000`, `WALL_SLIDE_FACTOR=0.8`, `DASH_SPEED=36000`, and a dash duration of approximately 0.25 seconds (`int(0.25 / delta)`). Jump and dash velocities are multiplied by `delta` in the source; the constants are not directly comparable to this project's px/s values.
- Observed behaviors: horizontal acceleration toward a capped speed, lerp-based neutral and airborne friction, jump cut on release of `ui_up`, coyote and floor-only buffered jump, wall jump that reverses facing, wall slide/grab, normalized eight-way input, gravity suppression while dashing, one ground-refilled dash, and animation selection by named `AnimationPlayer` clips. It creates a sprite trail during dash and requests camera shake/joypad feedback. The code contains a `yield` delay near a wall and direct input/action names; neither that blocking timing nor input wiring should be ported into the shared two-player executor.
- The inspected implementation has no standalone physics tuning resource and does not establish a Godot 4-compatible API or this game's match/CPU contracts. `player/player.tscn` uses a `RectangleShape2D` with extents (14, 20), offset about (0.257, 0.129), a rotatable 8×10 sprite sheet at scale ±2 and offset (1, -6), a 20 px wall ray, `AnimationPlayer` clips for red/blue idle, run, jump, fall, climb and wall slide, a light, and an 0.08 s trail timer. `scenes/Demo.tscn` instantiates the player over a Godot 3 `TileMap` backed by `assets/sprites/wall.tres`, with a background, particles, camera shake and audio. These geometry and animation details come from those concrete scenes; their TileSet is not reused in Keepy Uppy.
- Rights: GitHub presents an MIT license for the repository's code, while its README attributes the sprites to Nate Kling for Mix and Jam. The exact `LICENSE.md` is MIT for Yusuf Kaan Ocak’s code. The README attributes `playerSprites.png` to Nate Kling, and no separate license/permission for the sprites, tileset, or background appears in the inspected repository. The code license is not treated as sprite authorization.

## Visual asset authorization decision

No license or direct permission applicable to distributing repo A's Nate Kling graphics or repo B's EXOK-owned Celeste sprites in Keepy Uppy was found in the inspected repository notices. Hair behavior is implemented procedurally without copying reference sprites or source files. Code-level MIT status does not change the art decision.

# Design

## Context

See `proposal.md` for motivation. `MatchManager._finish_round` currently selects the opponent of the last valid toucher. The earlier active changes, `player-contact-and-downward-touch-rules` and `map-selection-tileset-arena-system`, have been reconciled to the clarified last-toucher rule. The match manager already stages player relocation and balloon activation, while the balloon controller owns warning presentation and the player controller checks wall jumps before grounded jumps.

## Goals / Non-Goals

**Goals:**
- Make the ground-contact winner and the expected next toucher explicit, separate values in round resolution.
- Ensure a set transition clears prior-round contacts and does not reinterpret a pre-existing overlap as a serve touch.
- Restore balloon presentation from the manager's expected player after the warning and impact presentation finish.
- Keep grounded jump initiation independent from horizontal wall-jump and player-bump displacement.

**Non-Goals:**
- Change who serves after a point or set, the point/set targets, or the downward-fault replay policy.
- Remove player collisions or reduce their configured push strength for ordinary movement.

## Decisions

- Award a ground-contact point to `last_valid_toucher`. Keep the no-touch fallback as the opponent of the opening server. Keep turn ownership separate: after a valid touch, the opponent remains the expected next toucher even though the last toucher receives the point if the balloon reaches the ground.
- Treat set completion as a new serve lifecycle. Clear pending normal and dash contacts, reset player and balloon contact state, reposition players, wait for placement to settle, then place the balloon. Do not accept overlap notifications generated by enabling the balloon as a new contact; a serve touch must be a fresh contact after arming. Guard deferred setup work against a restarted or completed match.
- Have the match manager update the balloon's current turn color whenever `expected_balloon_player` changes. Warning timeout restores that color. A valid contact may show its impact color briefly, then presentation resolves to the newly expected player's color. Point cleanup and reset may still restore the neutral base color.
- Consume a grounded jump request before attempting a wall jump. Trigger wall jump only when airborne and in contact with the applicable wall. Player-bump displacement may change horizontal velocity but must not overwrite a jump's vertical velocity.
- Keep all active change deltas aligned with the confirmed last-toucher outcome; when this change is archived, sync the main round-scoring spec to the same rule.

## Risks / Trade-offs

- [A balloon enabled while a player overlaps its contact area can emit an immediate body-entered event] → Keep contact disabled through setup and ignore existing overlaps when arming; accept a serve only from a fresh contact.
- [Color restoration can race with an impact tween or turn update] → Store the current turn color independently from impact color and restore it when the warning or impact presentation completes.
- [The main round-scoring spec still reflects the previous winner until this change is archived] → Apply the delta to the main spec before archiving and confirm the archived requirement awards the point to the last valid toucher.

## Migration Plan

Implement the scoring and turn-color changes, then update the set-transition serve lifecycle and jump ordering. Keep the earlier active scoring delta consistent and sync the main spec when archiving this change. No save-data migration is needed. Reverting restores the previous scoring outcome and presentation behavior.
